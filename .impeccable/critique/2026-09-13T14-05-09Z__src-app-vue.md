## Design Specificity Verdict

LLM assessment: Authored, not generic, but unevenly. The V/A/Roman-numeral grading system, alert-level water-status verdicts, GPX exporter, and region taxonomy are domain-built. The shell chrome (bottom pill toolbar, floating search card, sidebar list) is boilerplate map-app UI; no visual identity beyond two brand colors.

## Overall Impression

The app speaks its users' language and its best screen (the water-station verdict card) is confident, safety-literate design. But that quality doesn't reach the list you scan first, and reaching the actual verdict takes four clicks — working against the product's own 30-second-decision principle.

## What's Working

1. Water-station status card (WaterStationDetail.vue) — verdict-first, skeleton shaped like the final card, color-toned border.
2. Grade-tooltip system in RouteDetail.vue — teaches newcomers in place without slowing down users who know the codes.
3. URL-state sync directly serves the product's own "shareable to Line/FB" principle.

## Priority Issues

- [P0] Live conditions invisible from the list. CanyonList.vue rows show only static difficulty, never water/rain tone. Fix: surface a tone-colored dot on list rows once station data resolves.
- [P0] Silent hydrology gap. RouteDetail's status-strip renders nothing when no nearby station exists — indistinguishable from loading or broken. Fix: always render an explicit "no monitored station within range" state.
- [P1] Search card front-loads too many controls before any result appears (cognitive load: 4/8 checklist failures = high).
- [P1] RouteDetail Info tab is a flat 8-block stack with no visual grouping (matches an existing PRODUCT.md backlog item).
- [P2] No freshness signal on the compact status-strip (full detail view has a timestamp, the strip doesn't).
- [P3] Global loading overlay blocks the whole shell on first load instead of per-section skeletons.

## Persona Red Flags

Alex (Power User): URL-state and resizable panels serve Alex well, but must still open each route individually to see live conditions. activeTab resets to "Info" on every reopen, defeating a habitual "always check Hydrology first" pattern.

Jordan (First-Timer): Grade tooltips are hover/focus-only — undiscoverable on mobile despite PRODUCT.md naming "check on phone the morning of" as the primary use case. TW/NZ/Hydrology switcher has no explanation of what the modes mean.

Riley (Stress-Tester): If PocketBase or WRA/CWA APIs are down (an expected failure mode per PRODUCT.md), the app shows a full blocking error with only "Retry" — even locally-stored route/grade data becomes unreachable, though it doesn't depend on those external APIs.
