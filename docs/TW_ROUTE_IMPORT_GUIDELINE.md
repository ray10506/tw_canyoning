# Taiwan Route Import Guideline

這份文件用於新增或補齊台灣溪降路線。輸入可能只有 GPX、文字資料、來源網址或其中幾項；目標是建立一筆符合目前 TW Sidebar、路線 Panel、天氣與鄰近水文行為的 `canyon_routes` 資料。

共同規範：欄位與 JSON 依 [DATA_MODEL.md](./DATA_MODEL.md)，外部素材依 [SOURCE_AND_LICENSE_POLICY.md](./SOURCE_AND_LICENSE_POLICY.md)，發布流程依 [ADMIN_REVIEW_SOP.md](./ADMIN_REVIEW_SOP.md) 與 [RELEASE_CHECKLIST.md](./RELEASE_CHECKLIST.md)。

## 核心原則

1. 不猜測未提供的路線事實、難度、固定點或安全狀態。
2. 先審核資料與授權，再寫入 PocketBase。
3. GPX 的起點不一定是入溪點，必須配合 waypoint、路線說明與地圖判讀。
4. 天氣、雨量、水位與集水區資料只供判讀，不可寫成路線安全保證。
5. 使用外部 GPX、照片或手繪圖前，必須確認授權；保留來源連結不等於取得重製權。
6. 使用者必須先 review 變更；不要自行推送 Git。

## 兩個完成門檻

### 可送審

公開 API `POST /api/routes/submit` 至少需要：

- `name`
- `region`
- `grading`
- `gps`

API 回傳 `202 pending_review` 只代表資料已寄給管理員，不會自動建立或公開路線。

### 可發布

正式寫入 `canyon_routes` 前，下列欄位都必須有效：

| 欄位 | 規則 |
|---|---|
| `name` | 可辨識且穩定的中文路線名稱，不把整段說明塞進名稱。 |
| `region` | 使用「縣市 鄉鎮」格式，例如 `高雄 茂林`；這會影響搜尋與中央氣象署鄉鎮預報。 |
| `type` | TW 溪降路線固定為 `溪降`；缺少時前端不會載入。 |
| `grading` | 完整格式 `V# A# I-VI`，有公布星等才附上，例如 `V4 A3 III ★★`。 |
| `gps` | 已驗證的入溪點，格式固定為 `緯度, 經度`。 |

任何必要欄位無法確認時，保留在待審核清單，不要用 `0`、`未知`或猜測值硬建正式資料。

## 欄位優先級

### 有資料就必須收錄

| 欄位 | 判斷方式 |
|---|---|
| `name_en` | 有可靠英文名稱才填；不要只用未校對的拼音。 |
| `region_en` | 與 `region` 對應的英文縣市與鄉鎮，例如 `Kaohsiung · Maolin`。 |
| `max_drop` | 最大單一落差，不是總下降高度；統一附 `m`。 |
| `approach` | 從停車／接駁點到入溪點的實際進場方式。 |
| `total_time` | 完整行程時間；若來源只有分段時間，在 `note` 清楚拆開，不自行相加。 |
| `deep_pool` | 只使用 `有`、`無`、`不確定`；來源沒提就留空。 |
| `ab_shuttle` | 不需要時填 `不需要`；需要時寫明 A/B 點與安排方式。 |
| `note` | 資料來源、進出場提醒、分段時間、影片或外部 GPX 連結。不要重複其他欄位。 |
| `gpx_track` | 有可合法使用且驗證過的 GPX 時匯入。 |
| `gpx_waypoints` | 保留有導航意義的停車、岔路、入溪、出溪、撤退點與特殊地形。 |

### 系統衍生欄位

這些資料通常不要求投稿者手動提供，但發布前應完成或確認：

| 欄位 | 來源與規則 |
|---|---|
| `elevation` | 優先使用可信來源或 GPX；否則以已驗證的 `gps` 查詢海拔。填公尺數值，不附單位。 |
| `catchment_km2` | 使用集水區觀察員資料，填平方公里數值。 |
| `catchment_sampled` | 已完成集水區取樣才設為 `true`。 |
| `catchment_gps` | 實際取得 `catchment_km2` 的主流水系座標，不一定等於入溪點。 |

### 不需要為了完整而補的資料

- 未公布的星等、深潭、接駁、最大落差或英文名稱。
- 從照片自行推測的水量、固定點品質或難度。
- 重複的地址、裸距離、無來源的安全結論。
- 與路線無關的 GPX 點、裝置紀錄、心率、速度或時間戳。

## 接收資料時的處理順序

### 1. 建立來源清單

記錄每份資料的來源、日期、作者與使用權：

- 使用者提供的文字。
- GPX 原始檔與其作者／下載頁。
- 路線文章、影片或官方地圖連結。
- 照片與手繪圖的授權範圍。

來源衝突時不要靜默合併。優先採用較新、第一手且可核對的資料，並把差異列給管理員確認。

### 2. 檢查路線是否重複

用中文名、英文名、溪名、鄉鎮與附近 GPS 搜尋現有 `canyon_routes`。同一路線的新 GPX 應更新既有資料，不建立名稱略有差異的重複路線。

### 3. 驗證必要欄位

- `region` 必須能對應到台灣縣市與中央氣象署鄉鎮。
- `grading` 必須至少包含一個 V 級、一個 A 級與一個羅馬數字時間／承諾度級別。
- `gps` 使用十進位座標，緯度在前、經度在後；在地圖開啟後必須落在正確溪谷入口。
- `type` 必須是 `溪降`。

### 4. 檢查 GPX

GPX 應保留原檔，不先覆寫。匯入前檢查：

- 至少有一段含兩個以上點的 `<trkseg>`。
- 起終點與路線方向合理，沒有跨縣市跳點或 GPS 漂移造成的長直線。
- 多段軌跡保持分段，不能跨段連成直線。
- 有 `<ele>` 時確認單位為公尺且沒有明顯異常值。
- waypoint 名稱可理解，並依實際行程排序。
- 停車點不能誤當成 `gps`；`gps` 應是入溪點。
- 公開回報附件上限為 5 MB，格式只接受 `.gpx`。

目前 `gpx_track` 的資料形狀為：

```json
[
  [[24.123456, 121.123456, 820], [24.123500, 121.123600, 815]],
  [[24.124000, 121.124000, 790], [24.124100, 121.124200, 780]]
]
```

Waypoint 形狀為：

```json
[
  { "seq": 1, "lat": 24.123456, "lon": 121.123456, "ele": 820, "name": "入溪點" },
  { "seq": 2, "lat": 24.120000, "lon": 121.130000, "ele": 610, "name": "出溪點" }
]
```

### 5. 判斷海拔與集水區

海拔優先順序：

1. 可信路線資料明載的入溪點海拔。
2. GPX 入溪 waypoint 的海拔。
3. 已驗證 `gps` 的地形 API 查詢值。

集水區判斷：

1. 有多個溪中 waypoint 時，逐點取樣並保留屬於目標水系的合理最大值。
2. 只有單點時，以 `gps` 取樣，但先確認點位落在主流，不是在道路、山坡或支流外。
3. 若入溪點偏離主流，另選最接近路線且位於正確主流的點作為 `catchment_gps`。
4. 數值異常偏小時先修正取樣座標，不要直接接受結果。

目前可先執行自我檢查與預覽，不直接寫入：

```powershell
powershell -File scripts/backfill-catchment.ps1 -SelfTest
powershell -File scripts/backfill-catchment.ps1
```

`-Write` 會更新多筆路線；只有在檢查完整份預覽結果且確定要批次更新時才使用。

## 寫入 PocketBase

1. 先由管理員審核文字、座標、難度與來源授權。
2. 在 `canyon_routes` 建立基本資料，取得 record ID。
3. 有 GPX 且需要進 repo 時，先將原始檔存至 `public/gpx/tw/<route-slug>.gpx`，再執行匯入。GPX 是否存入 repo 由管理員在 review 時決定；暫時放置路徑使用 `scripts/` 或作業系統暫存目錄，不要把測試用的暫存 GPX 推進 Git。確認存放位置後，明確指定檔案與 record ID 後執行既有 importer：

```powershell
$env:GPX_PATH='C:\path\route.gpx'
$env:RECORD_ID='pocketbase_record_id'
$env:PB_EMAIL='...'
$env:PB_PASSWORD='...'
node scripts/import-gpx.mjs
```

不要使用 script 內的預設 GPX 路徑或 record ID。登入資料只放環境變數，不寫入程式、文件、終端紀錄或 Git。

4. 重新讀取該筆資料，確認 JSON 可解析、首尾點與 waypoint 數量正確。
5. 完成海拔與集水區欄位，再進行 UI 驗收。

## UI 驗收

### Sidebar 與地圖

- [ ] 路線出現在 TW Tab，名稱、完整難度、地區與最高瀑高正確。
- [ ] 點擊路線後 Sidebar 在手機自動收合，地圖 focus 到台灣正確位置。
- [ ] GPX 各段沒有錯誤連線，入溪與出溪 waypoint 位於正確地點。
- [ ] 有 GPX 與只有單點 GPS 的路線都能正常顯示。

### Route Panel

- [ ] 資訊順序維持：難度 → 地區 → 天氣 → 鄰近水文。
- [ ] 中英文名稱與地區沒有互換。
- [ ] 中央氣象署連結開啟正確縣市／鄉鎮，五日預報能載入。
- [ ] 鄰近水位站只取路線 5 km 內，距離欄位有「距路線」說明。
- [ ] 海拔、最大落差、集水區與距離都有單位。
- [ ] 集水區連結使用 `catchment_gps`，並實際落在正確水系。
- [ ] GPX 可下載，GPS 可開啟對應地圖位置。
- [ ] 缺資料時隱藏或顯示 `—`，不顯示假 `0`。

### 裝置與建置

- [ ] 桌面、390px 手機與直向平板沒有文字溢出、卡片觸邊或控制項重疊。
- [ ] 地圖在 Panel 開啟時仍可拖曳與縮放。
- [ ] `npm run build` 通過。
- [ ] `git diff --check` 通過。
- [ ] 未推送 Git，等待使用者 review。

## 匯入結果回報格式

每次匯入完成後，回報：

1. 新增或更新的路線名稱與 PocketBase record ID。
2. 寫入的必要欄位、選填欄位與衍生欄位。
3. GPX 原始點數、匯入點數、分段數與 waypoint 數量。
4. 使用的來源與授權狀態。
5. 仍缺少或互相衝突的資料。
6. 桌面、手機、地圖、天氣、鄰近水文與建置驗收結果。

## 可重複使用的請求

```text
依照 docs/TW_ROUTE_IMPORT_GUIDELINE.md 新增或補齊這條台灣溪降路線。

路線資料：
<貼上文字或來源網址>

附件：
<GPX、照片或其他檔案>

先判斷哪些資料達到可發布門檻，未確認的事實不要猜。檢查 GPX 的入溪點、分段、漂移、海拔與 waypoint，補齊正確鄉鎮、天氣、集水區及 5 km 內鄰近水文行為。寫入 PocketBase 後完成桌面與手機驗證，但不要推 Git。
```
